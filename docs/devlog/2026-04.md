# Development log - 2026-04

## 2026-04-27 - Made release install state self-cleaning

### Result

- A successful release now clears the local release binary directory rather
  than leaving the previous build in place.

### Why / context

- Stale binaries in the install directory shadow a newly released version, so
  the machine that performed the release is the one most likely to be running
  old code. Clearing after success makes the next invocation resolve the real
  installed version.

### Evidence

- `6fa9649c` feat(release): clear the local release bin directory after a
  successful release.

### Links

- `scripts/install-local-release-binaries.sh`

## 2026-04-26 - Replaced the shared AGENT_HOME root with per-tool roots

### Result

- `agent-docs` dropped `AGENT_HOME` / `--agent-home` and bound to
  `AGENT_DOCS_HOME` / `--docs-home` (breaking, `nils-agent-docs` 0.8.0), with
  an error when neither flag nor env is provided.
- `plan-issue-cli` replaced its own `AGENT_HOME` use with an explicit
  `--state-dir` (breaking).

### Why / context

- A single `AGENT_HOME` forced every consumer to share one root. Separate
  runtime kits need to pin their own docs root independently, which the shared
  variable made impossible without collisions.
- Erroring when both the flag and the env are missing was deliberate: the
  previous fallback silently resolved to a home-relative default, so a
  misconfigured consumer read an empty doc set and behaved as though no
  requirements existed.

### Evidence

- `6d159158` the `agent-docs` rename, `38ea6596` the `plan-issue-cli` move to
  `--state-dir`, `46514d8f` the third-party artifact refresh their version
  bumps required.

### Links

- `3b7c8eb9` refactor: standardize AGENT_HOME naming across workspace (the
  February convergence this reversed)

## 2026-04-26 - Gave plan-issue a canonical runtime layout

### Result

  and `RuntimeLayoutError`, declared the canonical `$ISSUE_ROOT` /
  `$SPRINT_ROOT` artifacts and gate G11 in the contract, state-machine, and
  gate-matrix specs, then cut `start-plan` and `start-sprint` over in separate

### Why / context

  (`efd05ba8` states this explicitly), so the cutover commits changed call
  sites only and were reviewable as such.

## 2026-04-25 - Cut test link time by collapsing integration targets

### Result

- Collapsed each crate's `tests/*.rs` files into a single
  `tests/integration.rs` plus a `tests/integration/` module tree, reducing the
  workspace from 254 linked test binaries to 25.
- Shrank dev debug info to line tables with unpacked split-debuginfo.

### Why / context

- Every `tests/*.rs` file is a separate binary that links the whole crate
  graph. At 254 of them, a one-line change to `nils-common` cost a 27-second
  rebuild dominated by linking, which made the local loop slow enough that
  people ran fewer checks.
- Measured effect: touch-`nils-common` rebuild 27s to 7s (3.8x), and
  `target/debug` from 26 GB to 4.3 GB. Line tables were kept so backtraces stay
  usable; only full DWARF was dropped.
- One knock-on: `screen-record`'s Linux-only tests wrap themselves in `cfg`
  gated `mod` blocks, which triggers the `module_inception` clippy lint once
  they share a target.

### Evidence

- `69e599e9` (#331) carries the measurements above in its commit body and the
  `module_inception` allowance for the Linux-only files.

### Links

- `Cargo.toml` dev profile debug settings

## 2026-04-15 - Fixed a shell injection and two input-handling defects

### Result

- Removed a shell injection path in the `fzf-cli` git-commit preview command.
- Fixed `git-cli back_checkout` SHA detection, which excluded all-digit
  candidates, and a panic in `image-processing` `color_has_alpha` on non-ASCII
  SVG input.

### Why / context

- The preview command was assembled as a shell string from a commit-derived
  value. Commit metadata is attacker-influenced in any repository you did not
  write, so this was reachable by cloning a hostile repository and opening the
  picker.
- The SHA rule excluded all-digit strings on the assumption that they were
  ordinal references. Short SHAs can legitimately be all digits, so the rule
  silently misrouted a valid checkout.
- `color_has_alpha` matched on `str::len()`, which counts bytes, then sliced at
  fixed byte indices. A two-byte UTF-8 character such as `#ffé` satisfies the
  four-byte arm and puts index 3 on a continuation byte, so slicing panicked.
  The fix rejects non-ASCII hex before the length match.

### Evidence

- `20e3e850` the injection fix, `fc087218` (#324) the SHA detection fix,
  `ee29ac94` the panic fix.

### Links

- `ecfe46f0` fix(completion): normalize bash completion labels
