# Development log - 2026-01

## 2026-01-31 - Added the API testing CLI family and its shared core

### Result

- Landed `api-rest`, `api-gql`, and the `api-test` suite runner on top of a new
  `api-testing-core` crate that owns suite setup, request execution, and
  summary reporting.
- Published zsh completions, wrappers, and install defaults for the new
  binaries in the same pass, and documented the family in the README and a
  usage guide.

### Why / context

- The three runners share almost all of their behavior: environment and token
  resolution, request history, report directories, and summary rendering.
  Putting that in `api-testing-core` from the first commit avoided three
  divergent copies, which is the mistake the ported shell scripts had already
  made.
- Parity specs were written before the runners (`e43ab3ca`) so the Rust ports
  had a stated target instead of being compared against the shell scripts
  after the fact.

### Evidence

- `b2248e32` (REST runner plus `api-testing-core`), `afa4c47a` (GraphQL
  runner), `10e4a547` (suite runner and summary).
- `92a2a07d` added zsh completions, `34a4418f` the wrappers, and `23cb2606`
  put the binaries in the default install set, so the surface shipped complete
  rather than as a binary with no integration.

### Links

- `40eb6276` docs(api-testing): add usage guide

## 2026-01-30 - Established the validation and install entrypoints

### Result

- Added `nils-cli-checks`, a single required pre-commit validation entrypoint,
  so contributors and agents run one command instead of remembering a list.
- Added a `nils-cli` install entrypoint plus completion and wrapper assets, and
  a `port-cli-to-rust` workflow skill capturing the port procedure with its
  own checks script.

### Why / context

- The workspace was being populated by a sequence of shell-to-Rust ports. A
  named entrypoint made the definition of "validated" a repository asset that
  could grow with the workspace, rather than instructions that drift in
  `DEVELOPMENT.md`.
- The port skill existed because the same porting steps were about to be
  repeated for a dozen tools; encoding them once kept the ports comparable.

### Evidence

- `e59b2c8c` added the checks entrypoint, `f9e766cc` the install entrypoint,
  and `784838d8` the port workflow skill.
- `42f25d99` made formatting checks a stated pre-commit requirement, and
  `7c95d277` closed the gap where newly added packages were not in the CI test
  list.

### Links

- `a11a865e` docs(development): add development guide
- `ce5c10ac` chore(ci): add dependabot and ci workflow

## 2026-01-30 - Bootstrapped the Rust CLI workspace and the first ports

### Result

- Created the Cargo workspace with `nils-common` and `cli-template` as the
  shared foundation, then landed the first ported tools: `git-scope`,
  `git-summary`, `git-lock`, `fzf-cli`, `semantic-commit`, and
  `image-processing`.
- Wired CI, Dependabot, and the MIT license on the same day the scaffold
  appeared.

### Why / context

- The workspace started as a consolidation target for a set of shell CLIs. The
  ordering was deliberate: a shared crate and a template crate first, so every
  port had a place to put common behavior instead of growing its own helpers.
- `semantic-commit` depends on `git-scope` for staged summaries. The
  dependency was first made hard (`658c1c27`) and then deferred (`b0d235ba`)
  so the binary stays usable when the companion tool is absent - the first
  instance of the graceful-degradation pattern that later became the
  `BINARY_DEPENDENCIES.md` contract.

### Evidence

- `7c2302ae` bootstrapped the workspace, `f1f1d7fd` the first port
  (`git-scope`), and `c8e926d0` the last of the day (`image-processing`).
- `4c588fca` fixed the first cross-environment test defect: `git-scope` tests
  assumed a default branch name, so they failed on machines configured
  differently.
