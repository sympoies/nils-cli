## 2026-03-08 - Made provider rate-limit fetching concurrent and renamed the prompt surface

### Result

- Added Gemini background prompt refresh and shared async rate-limit workers,
  and moved Codex async JSON rate limits onto the same bounded worker
  collection path, with deterministic concurrency regressions and parity
  contract guardrails.
- Renamed the `starship` command surface to `prompt-segment` across both
  provider CLIs, including env keys, cache paths, and completion aliases.

### Why / context

- Rate-limit fetching for all configured accounts was serial, so the prompt
  segment was as slow as the slowest account. A bounded worker pool fixed the
  latency without letting an account list turn into unbounded concurrency.
- The rename was a stated breaking change: the surface was named after one
  prompt tool it happened to be written for, while the output is a generic
  prompt segment. Keeping the old name would have implied a coupling that does
  not exist.

### Evidence

- `3d049a61` the concurrency work with its regressions and parity guardrails;
  `abdb0c13` the rename with docs, specs, and regression test updates.

### Links

- `b5d5693a` feat(codex-cli): add watch mode for async rate limits
- `16a212c6` feat(codex-cli): enforce rate-limits cache ttl behavior

## 2026-03-02 - Made third-party artifacts a deterministic, enforced contract

### Result

- Added a deterministic generation contract for `THIRD_PARTY_LICENSES.md` and
  `THIRD_PARTY_NOTICES.md`, a CI audit lane, regression coverage for both the
  generator and the audit script, and a release-tarball contract that fails if
  the packaged artifacts do not match.
- Added MPL source metadata to the notices.

### Why / context

- The artifacts had been generated once by hand (`afd8316a`, 03-01). Hand
  generation means the file is correct on the day it is written and wrong from
  the next dependency bump onward, with nothing detecting the drift.
- Making generation deterministic was the precondition for auditing it: a
  generator whose output varies run to run cannot be compared against a
  committed file. The audit then makes every dependency change either refresh
  the artifacts or fail.
- This is why a Dependabot bump in this repository can fail CI on a licenses
  diff rather than on a build error, and why the refresh is part of release
  prep (`f7c35b69`).

### Evidence

- `4bab8963` (#276) the generation contract, `bac3342a` (#277) generator
  regression coverage, `4b6df7d8` (#278) the CI audit lane, `42d2a83d` (#279)
  audit script regressions, and `206fa831` (#280) the tarball contract.
- `7f6b69a7` had to install ripgrep in CI for the tarball audit, and
  `e9691ccf` added the MPL source metadata the audit surfaced as missing.

### Links
