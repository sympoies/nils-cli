# Development log - 2026-07

## 2026-07-31 - Fenced the main-agent closeout path

### Result

- Added a fenced main-agent closeout and a fenced post-claim runtime stop, and
  closed the B2 recovery boundary in the release workflow.

### Why / context

- Closeout and stop are the two operations where a stale actor can undo a newer
  one's work: a worker that was superseded still believes it owns the session.
  Fencing makes the operation carry the generation it was issued under, so a
  superseded actor's closeout is refused rather than applied late.
- This is the same generation-fencing pattern the workspace lease protocol
  adopted in September.

### Evidence

- `9ebbc922` the fenced closeout, `2f440ecc` the fenced post-claim stop,
  `7d0b6319` the recovery boundary fix.

## 2026-07-27 - Replaced local-default with an explicit default-branch command

### Result

- Replaced the `local-default` delivery target with `default-branch`, making it
  the sole exceptional local delivery command, and hardened main-agent
  supervision, recovery, and coordination contracts alongside it.

### Why / context

- `local-default` read as a mode - something that could be on by default -
  when it is in fact a named exception requiring current-request approval. The
  rename makes the invocation state the exception it is taking.
- This is the command the repository policy still points at: a commit to the
  default branch is only permitted through `semantic-commit default-branch`
  with explicit approval, and every other path goes through a managed worktree.

### Evidence

## 2026-07-24 - Added governed execution capsules to codex-cli

### Result

- Added governed execution capsules: prepared scripts run only through
  sandbox-attested Codex helpers, with private receipts preserved for failure
  analysis, versioned JSON schemas, and stated host and workspace trust
  boundaries.
- Disabled MCP by default for supervised agent runs the following day.

### Why / context

- The capsule exists so an already-authorized local operation can be reviewed
  as a script before it runs and audited afterwards, instead of being a command
  an agent assembles and executes in one step. The receipts are private because
  they contain the failing command's environment.
- Disabling MCP by default under supervision narrows what a supervised run can
  reach without a deliberate opt-in - the same fail-closed default the rest of
  the runtime work adopted.

### Evidence

## 2026-07-23 - Built the mailbox delivery pump for main-agent orchestration

### Result

- Added durable main-agent orchestration with typed workflows over
  authenticated durable state, main-agent rebind with transient-store auto
  retry, worker wait-completion long-poll, last-prompt continuity state, and a
  mailbox stack: notification generations, cross-transport scheduling, a
  controller-owned delivery pump, delivery to a managed Claude session, and
  safe outcome projection.
- Added structured session recovery to `agent-docs` and local-only workflow
  contracts to `agent-runtime`.

### Why / context

- Notifications to a managed agent session are not a simple write: the target
  may be busy, restarting, or superseded. Generations make a late delivery
  identifiable, and a controller-owned pump means exactly one component decides
  when a notification is attempted, instead of every producer retrying on its
  own schedule.
- Projecting outcomes safely matters because a delivery result is reported back
  into an agent's context; an unbounded or unredacted outcome would be both a
  context cost and a leak surface.

### Evidence

- `21fcd1d1` the orchestration base, `8cdaa19b`, `c7bbf711`, `4a209780` the
  rebind/long-poll/continuity work, `95a731e4`, `0ace11cd`, `6bff7c93`,
  `85edd333`, `a0e8f0aa` the mailbox stack.

## 2026-07-21 - Added OS-enforced inspection and the read-only effect contract

### Result

- Added OS-enforced Linux inspection to `agent-run` and clarified macOS
  fail-closed inspection, gave `agent-hook` a read-only operation effect
  contract, and bounded the `forge-cli` review delivery lifecycle while making
  threaded reviews resumable.
- Moved Linux ARM64 release builds to native runners.

### Why / context

- "Read-only" asserted by a tool is not read-only; OS-enforced inspection makes
  the claim checkable. On macOS, where the same enforcement is unavailable, the
  path fails closed instead of silently degrading to an unenforced claim -
  which is the only honest option.
- Resumable threaded reviews matter because a long review can exceed a single
  run; without resumption the choice was to restart and duplicate comments, or
  to abandon the partial review.

### Evidence

- `f5ed1f4e` (#1337) and `0a3c85af` (#1344) the inspection work, `7ac3e54e`
  (#1335) the effect contract, `e2d1c105` (#1333) and `9d80c5e5` (#1338) the

## 2026-07-20 - Added the agent-hook control plane and authenticated coordination

### Result

- Added `agent-hook` as a shared hook control plane with strict schemas,
  provider normalization, deterministic aggregation, setup ownership, recovery,
  and coordination liveness, then sequenced coordination inside owned ingress.
- Added authenticated session coordination to `agent-session`: atomic
  work-context claims, mutation admission, fail-closed recovery, and a bounded
  private mailbox with body-free idle notifications across CLI and HTTP.

### Why / context

- Coordination is advisory by design in this workspace - it reports collisions,
  it does not authorize work. Making the claims authenticated and atomic was
  what allowed that advisory signal to be trusted at all: an unauthenticated
  claim tells you only that something claimed something.
- Idle notifications are body-free on purpose. A notification's job is to say
  that something changed; carrying the content would put another session's data
  into this session's context with no consent step.
- The control plane started from a frozen contract with a captured failing test
  (`8c65fd02` describes exactly this), so the compatibility-forwarding behavior
  was pinned before any production edit.

### Evidence

- `8c65fd02` (#1314) the control plane, `4a719a8f` (#1330) ingress sequencing,
  `afd722dc` (#1334) the single-sourced registry cap, `b8cedc78` (#1308) the
  authenticated coordination with its v1 contract and regenerated completions.

## 2026-07-16 - Replaced the macos-agent native engine with a Peekaboo adapter

### Result

- Replaced the native macOS automation engine with a Peekaboo adapter that
  pins, verifies, installs, and rolls back reviewed releases, proxying local
  and SSH execution through policy, journal, scenario, and MCP contracts.
- Replaced the native-engine test coverage with adapter, supply-chain,
  lifecycle, and fault tests.

### Why / context

- Maintaining an in-tree AX automation engine meant tracking macOS accessibility
  behavior changes indefinitely for a capability that was not the workspace's
  purpose. Adapting to an external engine moved that burden out, at the cost of
  a supply-chain dependency - which is why pinning, verification, and rollback
  are part of the adapter rather than an operator procedure.
- Replacing the test suite rather than keeping both was deliberate: engine
  tests that no longer exercise the shipped path are the stale tests the
  repository's audit exists to catch.

### Evidence

- `2e55e376` (#1234) the replacement; `9ee1656c` (#1478) upgraded the pin to
  4.2.2 in August, exercising the rollback-capable pinning path.

## 2026-07-12 - Made provider sessions resumable and usage-aware

### Result

- Added durable provider turn state, Claude input-attention correlation, the
  ability to resume Codex and Claude sessions from their original working
  directory (via a new `nils-provider-resume` crate), resumption after a usage
  reset, and Codex app-server auto-resume.
- Added unified provider usage exposure with failure-reason classification, and
  `agent-memory` recall with candidate promotion.

### Why / context

- A provider session that hits a usage limit used to be lost. Making turn state
  durable and resumption usage-aware turned a terminal failure into a wait,
  which is the difference between an agent run that survives a rate-limit
  window and one that does not.
- Resuming from the original working directory matters because a provider
  session's history is only meaningful relative to the repository it was
  started in; resuming elsewhere produces confidently wrong context.
- Classifying failure reasons (`2870234d`) was the precondition for any of
  this: "the provider failed" cannot drive a retry decision, while "usage
  exhausted, resets at T" can.

### Evidence

- `993e3145` (#1091) durable turn state, `5a5ff8fa` (#1096) cwd-faithful
  resume, `94e22e51` (#1127) usage-reset resume, `8b0c5491` (#1154) app-server
  auto-resume, `e8946604` (#1078) unified usage, `2870234d` (#1112) failure
  classification.

## 2026-07-05 - Gave agent-session an HTTP control plane and WebSocket PTY attach

### Result

- Added `serve`: an axum daemon on a scoped tokio runtime - the first server in
  the workspace - exposing health, session list, glance, create, send, delete,
  and a WebSocket attach endpoint. Handlers reuse the existing synchronous
  lifecycle functions through `spawn_blocking`, so there is no second
  implementation of session lifecycle.
- Extended the control plane with a curated workdir repo picker, sessions
  resumable beyond tmux, tmux paste-buffer exposure, and repo remote browser
  URLs.

### Why / context

- Reusing the synchronous lifecycle via `spawn_blocking` rather than writing
  async equivalents was the central decision. Two lifecycle implementations
  would have drifted immediately, and the CLI path is the one with the longer
  test history.
- Making sessions resumable beyond tmux (`fe7a2888`) decoupled the session
  concept from the multiplexer, which is what later allowed external runtime
  providers to participate.
- Running the tmux server in its own systemd scope (`1ab84cbe`) stopped session
  processes from being killed with the launching shell's cgroup.

### Evidence

- `664146b9` (#1015) the daemon with its endpoint list, `90ff532f` (#1019) the
  extension, `fe7a2888` (#1023) resumability, `1ab84cbe` (#1035) the systemd
  scope.

## 2026-07-03 - Added the tmux-backed agent session CLI

### Result

- Added `agent-session` with Codex and Claude tmux session start, run, list,
  attach, logs, and delete commands, persisting prompts and session metadata
  without printing prompt content, with completions, docs, publish order, and
  third-party artifacts registered in the same change.

### Why / context

- Prompt content is persisted but never printed. That split is the crate's
  founding constraint: session metadata has to be inspectable for listing and
  recovery, while prompts are user content that must not appear in logs, list
  output, or an agent's context by accident.
- tmux was chosen as the first backend because it already solves detach,
  reattach, and process survival. The abstraction was kept thin enough that
  sessions became resumable beyond tmux three weeks later.

### Evidence

- `d591f805` (#1009); `3ad698a3` (#1013) added the send and glance verbs plus
  the hermes interactive kind two days later.

## 2026-07-01 - Added dynamic shell completion via CompleteEnv

### Result

- Added a `completion_engine` dimension to the completion audit, and dynamic
  completion for `git-cli` worktrees, `agent-memory`, and `secrets`, plus
  `git-cli worktree go` and a primary-root fix.

### Why / context

- Static completion can only offer flags and subcommands. The values people
  actually need completed - worktree slugs, memory names, secret keys - only
  exist at runtime, so clap's `CompleteEnv` support was wired in for the
  commands whose arguments are runtime-resolved.
- The audit needed a new dimension because a dynamically-completed command
  legitimately has no static value list, and the existing audit would have read
  that as missing coverage.

### Evidence

- `2e7e3288` (#1000) the audit dimension, `de62260d` (#1002) the `git-cli`
  dynamic completion, `85575cce` (#1004) `agent-memory` and `secrets`,
  `84ebf083` (#995) `worktree go`.
