## 2026-06-27 - Completed the forge-cli review-thread write surface

### Result

- Added review-thread resolve and reply, native review-event mode on
  `pr review`, creation of resolvable review threads, and review-thread
  preflight validation.

### Why / context

- Reading review threads was already possible; acting on them was not, so an
  agent could see unresolved feedback and had no way to answer it in place.
  Creating threads as resolvable rather than as plain comments is what makes
  the resolution state meaningful afterwards.
- The preflight exists because thread creation fails in ways that are only
  visible after the fact - an invalid file or line anchor produces a thread
  attached to nothing - and a review that silently lands nowhere is worse than
  a refusal.

### Evidence

- `9554252b` (#883) resolve/reply, `3a7680c7` (#947) native review-event mode,
  `803928e4` (#951) resolvable threads, `3ef445f6` (#973) the preflight.

## 2026-06-25 - Gave agent-memory structure checks and a query surface

### Result

- Added a `check` command for structural integrity, plus a note writer and
  structured `list` and `search` commands.

### Why / context

- The memory store is a directory of Markdown files with frontmatter, written
  by agents under time pressure. Without a structural check, a malformed entry
  is discovered at recall time, which is the worst moment. `check` moved the
  failure to write time.
- `list` and `search` being structured rather than text output is what lets
  recall be bounded: a caller can select relevant entries instead of loading
  the whole store.

### Evidence

- `3aa91b2a` (#941) the check command, `279cd556` (#942) the writer and query
  commands.

## 2026-06-21 - Cut two dependency risks out of the tree

### Result

- Switched the `jsonwebtoken` crypto backend from `rust_crypto` to `aws_lc_rs`,
  eliminating `rsa 0.9.10` (RUSTSEC-2023-0071, Marvin timing attack) and
  roughly 27 transitive crates.
- Replaced the Tera templating engine with minijinja 2.x in `nils-markdown`'s
  engine and `agent-runtime`'s render helpers, dropping duplicate `pest` and
  `chrono-tz` trees.
- Wired `cargo-deny` advisories and duplicate-version bans into CI.

### Why / context

- `aws-lc-rs` was already compiled into the tree through reqwest's rustls, so
  the swap removed an entire elliptic-curve and bignum stack without adding
  anything new. That made an advisory fix also a build-time win.
- The minijinja port had to preserve byte-identical output: the `md_cell`
  filter and the script, `skill_ref`, `state_out`, and `cli_ref` helpers were
  ported with the same argument validation and error behavior, autoescape
  disabled, and trailing behavior preserved - because `nils-markdown`'s
  determinism gate and every golden test depend on exact bytes.
- `cargo-deny` landed in the same week so the next such advisory surfaces in CI
  rather than in a manual audit.

### Evidence

- `e71ab544` (#930) the crypto backend swap with the advisory and crate counts
  in its body; `f734b24f` (#931) the templating swap; `19449eb5` (#933) the
  `cargo-deny` wiring.

## 2026-06-19 - Added GitHub App token minting and the SOPS secrets store

### Result

- Added `github-app-cli` with `token`, `installations`, and completion
  subcommands, signing the App JWT in-process with RS256 and calling the REST
  API directly, with no new external binary dependency.
- Added the `nils-secrets` crate (binary `secrets`) over a SOPS plus age store
  keyed by the repository git origin, with pull/add/list/which/edit.
- Consolidated `plan-issue`'s GitHub provider operations onto `forge-cli`.

### Why / context

- Both crates enforce a no-secret-leak contract at the output boundary rather
  than by convention. `github-app-cli` emits the raw token only on stdout in
  text mode, for `GH_TOKEN` capture, while JSON mode returns non-secret
  metadata. `secrets pull` streams `sops -d` straight into a mode-600 `.env`,
  and both JSON and human output stay metadata-only. Hermetic contract tests
  cover the leak-safety paths.
- Signing the JWT in-process was a deliberate choice against shelling out: an
  external signer would have added a runtime binary dependency to the one path
  that must work before any other credential exists.
- Consolidating `plan-issue` onto `forge-cli` removed the last place where two
  crates spoke to GitHub with different retry, rate-limit, and error handling.

### Evidence

- `11e07b56` (#903), `c3e807f2` (#906), `a0600a34` (#908).

### Links

- `BINARY_DEPENDENCIES.md` SOPS and age prerequisites

## 2026-06-14 - Split scrub into a shared crate and added the evidence archive

### Result

- Extracted the shared `nils-scrub` crate out of `plan-archive`.
- Added `nils-evidence` (binary `evidence`) with migrate, discover, query,
  search, catalog, and validate commands over a durable skill-usage evidence
  archive, mirroring `plan-archive`'s structure and depending on `nils-scrub`
  for redaction.
- Made `skill-usage` stamp the producer tool and the `nils-cli` version on each
  record, and gated `pr create` on test-first evidence through config.

### Why / context

- Two archives needing the same redaction is the point at which the redaction
  becomes a crate rather than a module. Sharing it also means a scrub rule
  added for one archive protects the other.
- `evidence migrate` uses rollup-per-run grain and is dry-run first with
  `--apply` gated, for the same reason `plan-archive migrate` was: a bulk
  transform over records you cannot regenerate should show its work.
- Stamping the producer and version makes an archived record interpretable
  later; without it, a record's format is ambiguous once the emitter changes.

### Evidence

- `c627e795` (#846) the extraction, `5f404bd2` (#848) the evidence CLI,
  `87886b82` (#844) the stamping, `5ff4e83c` (#836) the PR create gate.

## 2026-06-12 - Made pr merge fail closed on unresolved review state

### Result

- Added `pr review-threads` with normalized state across the GitHub
  `reviewThreads` GraphQL connection and GitLab resolvable discussions, and
  merge lock-down rule 12 (`review_threads_resolved`).
- Added a second gate on unchecked task-list items.

### Why / context

- `pr merge` and the `pr deliver` merge step fetch review threads immediately
  before the backend call and fail closed with `unresolved_review_threads`
  (DATA 65), listing each thread. The immediate fetch is the point: bot
  reviewers post asynchronously, so a thread can appear between an earlier
  check and the merge, and a cached result would let exactly that case through.
- The local provider returns an empty list because it has no thread model,
  which keeps offline plan runs from being blocked by a gate that cannot apply.

### Evidence

- `f13cb705` (#809) the review-thread gate, `a64a62b0` (#815) the task-list
  gate.

### Links

- `90944083` the original May lock-down chain this extends

## 2026-06-01 - Dropped the -cli suffix and enforced the naming convention

### Result

- Renamed `agent-runtime-cli`, `memo-cli`, and `plan-issue-cli` to drop the
  `-cli` suffix from crate directories, libraries, and contract namespaces, and
  renamed the `nils-cli-*` skills to a `project-*` prefix.
- Added CI enforcement of the crate and CLI naming convention, and an opt-in
  `[skills]` skill-name prefix lint in the `agent-docs` audit.

### Why / context

- Every crate in this workspace is a CLI, so `-cli` carried no information
  while making binary names, crate names, and contract namespaces inconsistent
  - some had the suffix, some never did. The rename picked the shorter form and
  made it uniform.
- Renaming `plan-issue`'s contract namespace was the breaking part: the JSON
  schema version strings change with it, so consumers pin a new namespace.
- Both lints landed alongside the renames so the convention is checked rather
  than remembered. The skill prefix lint is opt-in per repository because not
  every consuming repository uses the same skill naming scheme; this repository
  enables it in `AGENT_DOCS.toml`.

### Evidence

- `1317bf5e` (#728), `2bc2ddb7` (#731), `223cfa42` (#735) the renames;
  `8a202ed5` (#729) the skill rename; `a1279bcc` (#730) and `048aa19d` (#733)
  the lints.
