  through it, and added GitHub activity discovery plus `search issues/prs` and

## 2026-05-30 - Blocked machine-local paths in posted text

### Result

- `forge-cli` now blocks machine-local home paths in text it posts to issues,
  pull requests, and comments.
- `agent-docs` gained `required=false` opt-out for builtin requirements and a
  data-driven catalog with content-emitting preflight.

### Why / context

- Agents generate issue and PR bodies from local runs, so absolute home paths
  leak into public text routinely. They identify the operator, disclose
  directory layout, and are useless to every reader. Blocking at the posting
  boundary catches all producers at once, which is why the repository's
  `portable-paths` guidance is enforceable rather than advisory.
- The `required=false` opt-out exists because consuming repositories inherit
  builtin doc requirements that do not apply to them; without an opt-out the
  only escape was to stop declaring intents at all.

### Evidence

- `97261c63` (#683) the path block, `6cb2a84c` (#658) the opt-out, `7ea5563e`
  (#671) the data-driven catalog.
- `0247278d` (#690) and `47edca71` (#691) added `plan-archive` body-search and
  the `search` subcommand over archived bodies and comments.

## 2026-05-29 - Added agent-memory, build metadata, and graceful rate-limit degradation

### Result

  crate.

### Why / context

- Null rate-limit windows are a normal provider response, not an error

## 2026-05-26 - Made Markdown generation a template layer

### Result

- Landed `nils-markdown` as a render template layer, then migrated nine Tier A
  emitters onto it in one day: the `plan-issue-cli` task-decomposition block,
  lifecycle templates, `render.rs` emitters, the record dashboard, snapshot and
  comment posting, `execute.rs` emitters, and the `review-specialists`,
  `repo-retro`, and `heuristic-inbox` renderers. Shipped the `md-render`
  binary and runbook.

### Why / context

- The stated principle in the plan is that templates carry layout only and data
  is prepared as flat structs. The previous emitters interleaved both, so a
  layout change meant editing string concatenation inside business logic and
  every change risked a payload defect.
- Doing all nine migrations in one pass kept the two representations from
  coexisting. The closeout Required-column rendering defect (`f2666c47`) was
  found precisely because the templates made the layout inspectable.

### Evidence

- `2e6352be` (#542) Sprint 1 with the plan bundle; `49e01395` (#543) through
  `763be0dc` (#552) the nine migrations; `a6085863` (#553) the binary and
  runbook.

## 2026-05-21 - Finished the destructive-operation guardrails

### Result

- Hardened the `git-lock` destructive safety workflows and completed
  workspace-wide destructive operation guardrails, alongside progress display
  and default limits for long-running commands.

### Why / context

- Several CLIs could destroy work with a single flag and no preview:
  lock removal, worktree removal, backup restore. The guardrails standardized
  the shape - preview, explicit confirmation or an explicit force, and a
  bounded default - so a caller does not have to know which command is the
  dangerous one.
- Default limits matter for the same reason in the other direction: an
  unbounded query against a large repository looks like a hang, and people
  interrupt it in states that are harder to recover than a truncated result.

### Evidence

- `eb7c3713` hardened the `git-lock` destructive workflows; `a9b4803b` completed the
  guardrails; `f08a7018` added progress and default limits.

## 2026-05-20 - Built forge-cli as an atom-per-operation forge client

### Result

- Scaffolded `forge-cli` and carried it through eight sprints in one day: auth
  and repo atoms with `--dry-run`, PR atoms (create/view/list/edit/comment/
  ready/close), check atoms (`pr checks`, `pr wait-checks`), a `.forge-cli.toml`
  loader, a TTL-zero required-check gate, the `pr.merge` atom with a six-rule
  lock-down chain, issue atoms, the `pr.deliver` macro, and a parity harness
  with an exit matrix and fixture lint.
- Migrated the dispatcher CLIs to clap across three sprints and standardized
  root help discoverability.

### Why / context

- The merge path is where an automated forge client can do real damage, so it
  got the strictest contract: dirty worktree, draft merge, default-branch
  protection, required checks green, unsupported merge method, and keep-branch
  conflict are each a named refusal rather than a generic error. The
  required-check snapshot is re-taken with TTL zero immediately before merging,
  because a cached green result is exactly the thing that must not be trusted
  at that moment.
- Configuration precedence was fixed explicitly - CLI flags beat per-repo
  `.forge-cli.toml`, which beats the spec default of squash plus branch
  deletion - so the outcome of a merge is predictable from the invocation.
- Building atoms first and the `pr.deliver` macro last kept the macro a
  composition rather than a second implementation.

### Evidence

- `7c06dcd7` scaffold through `70be1f1f` Sprint 8; `90944083` carries the
  lock-down rule list and precedence chain in its commit body.

### Links

- `.agents/skills/pr` and the `pr:deliver-pr` workflow

## 2026-05-19 - Made the CLI output envelope a shared contract

### Result

- Added `nils_common::cli_contract`: `OutputFormat`, `Envelope<T>` with
  `EnvelopeError`, BSD sysexits-aligned exit constants, `schema_version_for`,
  and `emit_parse_error`, with `cli-template` migrated as the reference
  implementation.
- Migrated `memo`, the eight agent-workflow primitives, and the API binaries
  to the shared envelope (all breaking), then fanned the shared exit codes and
  a v2 staged-context schema out to fourteen more binaries, and added a CI lint
  with a self-test.

### Why / context

- Every CLI had invented its own JSON shape and exit codes. For agent callers
  that meant per-binary parsing and per-binary error interpretation, which is
  the cost the workspace exists to avoid.
- Aligning exits with BSD sysexits (usage errors become 64, not 2) was the
  breaking part. `8dce2288` realigned `agent-docs`, `image-processing`, and
  `plan-issue-cli` and updated their parity assertions in the same commit.
- The staged-context v2 schema shipped duplicated camelCase aliases for one
  minor cycle rather than breaking consumers immediately - a deliberate,
  time-boxed compatibility window rather than an open-ended one.
- `--json` became a hidden alias of `--format json` everywhere, so the old
  invocation keeps working without advertising two ways to ask.

### Evidence

- `0f6ea1b4` the primitives and reference migration, `7c8c02d7`, `9387ec9f`,
  `fdaf5d6a` the breaking migrations, `8dce2288` the fan-out, `d59ee622` the
  lint and self-test, `1ece512f` the remaining alias hiding.

## 2026-05-19 - Enforced plan source contracts in plan-tooling

### Result

  slug plans scaffolded into folders, bundle auditing, an error catalog with

  repeated errors grouped, a `spec` subcommand, a `--fix` mechanical-rewrite

### Why / context

## 2026-05-11 - Added agent-out as the canonical output path owner

### Result

  and layout audits, with workspace metadata, docs, completions, tests, and

### Why / context
