## 2026-08-30 - Unified provider review publication

### Result

- Made review publication render one canonical table report with explicit
  actionable line and file threads, validate specialist reports, and publish
  concise personal metadata without duplicating native App review bodies.

### Why / context

## 2026-08-28 - Made default-branch resolution evidence-only

### Result

- Removed the caller-asserted default-branch flag and the conventional-name
  list that guarded it, resolving the default branch only from evidence.
- Added a governed first-branch publish for an empty remote.

### Why / context

- The name list was a guard that only stopped honest callers. A caller who
  named a branch outside the list cleared exactly the push that the truthful
  name would have been refused for, so the check inverted its own intent: it
  penalized accuracy and rewarded an arbitrary name.
- Removing it was only safe once both ends were covered: an empty remote gets a
  governed bootstrap publish, and a populated one has real evidence to resolve
  from. The commit body states this ordering explicitly.
- This is a useful precedent for the workspace's guard design generally - a
  check that depends on the caller describing itself accurately protects
  nothing.

### Evidence

- `ed0d38c9` (#1544) the removal with its reasoning, `e4883db7` (#1540) the
  empty-remote publish it depends on.

## 2026-08-27 - Bound delivery to exact bases and added durable acceptance verdicts

### Result

- Enforced the requested PR or MR base through lookup, creation, readiness, and
  merge, and added a fast-forward-only owner for synchronizing published
  non-default branches.
- Added durable acceptance verdicts to `agent-hook`.

### Why / context

- A base branch resolved once at creation and re-derived later can differ, so a
  PR could be merged into a branch the requester never asked for. Enforcing the
  exact base at every stage removes the window instead of narrowing it.
- Restricting integration-branch synchronization to fast-forward-only means the
  operation can never discard a commit; anything that would require a
  non-fast-forward is a refusal the operator resolves.

### Evidence

- `342e71e0` (#1533) the base binding and fast-forward owner, `7d872fff`
  (#1507) the acceptance verdicts.

## 2026-08-24 - Added the native workspace lease authority

### Result

- Added a native workspace lease authority to `agent-hook`: physical git
  worktrees canonicalized behind private keyed identities, durable
  cross-process mutations fenced with strict idempotent lifecycle calls, and
  coverage for contention, replay, recovery, privacy, and the public CLI
  contract.

### Why / context

- Two agents working the same checkout is the collision the coordination layer
  had been reporting advisorily. A lease makes it enforceable for the
  operations that actually conflict, without turning coordination into
  admission control everywhere.
- The identities are keyed and private because a lease key derived from a
  readable path would disclose machine-local directory layout to every peer
  that can read the registry.
- Idempotent lifecycle calls matter because the caller is an agent that may
  retry: a lease acquire that is not idempotent turns a retry into a
  self-deadlock.

### Evidence

- `8f6c59bd` (#1488); `e2bdb199` (#1497) added the transactional DSH
  prerequisites to `agent-docs` the next day.

### Links

- `556067bd` (#1600) the September target-scoped v2 protocol

## 2026-08-19 - Added DSH as an external-runtime main-agent provider

### Result

- Added strict DSH ingress to `agent-hook`, normalizing bounded
  `agent-hook.dsh-ingress.v1` pre-tool requests into the shared policy engine
  while keeping DSH registration bundle-owned.
- Added `AgentKind::Dsh` to `agent-session` with typed refusals on every
  tmux-launch, provider-resume, one-shot-run, and activity-configuration
  surface, reporting the external-runtime contract from
  `main-agent capabilities`.
- Added native DSH runtime integration and corroborated a DSH lane stop with
  its broker.

### Why / context

- A DSH session is owned by an external runtime, so `agent-session` must never
  launch, resume, or configure it. Encoding that as typed refusals on each
  surface - rather than as documentation or a silent no-op - means a caller
  gets a specific, actionable error instead of a session that appears to start
  and does not.
- Corroborating a lane stop with the broker (`3d1124cf`) closed the case where
  the local view believed a lane had stopped while the external runtime still
  had it running.

### Evidence

- `5937233a` (#1465), `9913c3da` (#1467), `4dd196d6` (#1468), `3d1124cf`
  (#1471).

## 2026-08-05 - Recovered the release workflows and restored the coverage gate

### Result

- Restored the required `main` checks, including Linux canary fixtures and
  fail-closed macOS compilation boundaries, with refreshed audited
  dependencies, notices, and publish order.
- Recovered the squash-tag release workflows: squash-merged release PR CI is
  trusted only when the tested head tree matches the tagged commit tree, and
  exact-tag recovery dispatches and reruns are authorized through tested broker
  identity and ref guards.
- Restored the 85% line-coverage gate by covering the worst-covered production
  surfaces first, and made the release verify the tap formula rather than the
  dispatch acknowledgement.

### Why / context

- Tree-equality is the right trust condition for a squash merge: the squashed
  commit is a different commit from the one CI tested, so trusting the PR's
  green status by identity would trust a result for different content. Comparing
  trees checks the thing that actually matters.
- Verifying the tap formula instead of the dispatch ack closed the same class
  of gap on the publishing side - an accepted dispatch is not a published
  formula.
- The coverage restoration was targeted rather than broad: the review-loop
  ledger and merge gates, `agent-out` cleanup apply, the `agent-docs` catalog
  parser, resolver and renderer, doctor coverage and probe reporting, and the
  direct-push and repo-bootstrap guards - the paths where an untested branch is
  a delivery risk, not the paths that were cheapest to cover.

### Evidence

- `df07d8a0` (#1397), `c57e708b` (#1402), `1f2905db` (#1408), `60d26137`
  (#1450).
- `ce3d3add` (#1433) made `nils-test-support` skip on an absent or stale

## 2026-08-04 - Made the review loop verifiable offline

### Result

- Made `review-loop observe --dry-run` faithful to the live path, and added
  offline validation of a review-loop findings file.

### Why / context

- A dry run that takes a different code path than the live run is worse than no
  dry run: it produces confidence about behavior it does not exercise. Making
  it faithful was the prerequisite for using it as a review-time check.
- Offline findings-file validation means a malformed review payload fails
  before anything is posted, rather than producing a partially-published review
  that has to be cleaned up by hand.
