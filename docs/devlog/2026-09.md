# Development log - 2026-09

## 2026-09-14 - Hardened the dependabot apply workflow's pull-request selection

### Result

- Both jobs in `dependabot-third-party-apply.yml` now select the bump's pull request with
  `--jq '[.[] | select(.isCrossRepository == false)][0]'` instead of taking `.[0]`, so a
  same-named branch in a fork can no longer be chosen.
- The workflow-level concurrency group is scoped to the verified commit
  (`workflow_run.head_sha`) rather than the branch.

### Why / context

- `gh pr list --head <name>` filters on the branch name regardless of which repository the
  branch lives in, and this repository is public with forks. An outside user could open a
  pull request from a fork branch named like a Dependabot branch, become the first element
  of the result, and fail the `dependabot[bot]` author check — turning the privileged
  commit job red and stranding that bump's artifact refresh. It is an availability problem,
  not a privilege one: the author and head-SHA gates still hold.
- The qualification cannot move into the flag. `gh pr list` documents that the
  `<owner>:<branch>` form is *not supported*; passing it matches nothing, which silently
  turns the whole automation into a no-op. That was verified the hard way in the sibling
  `nils-alfredworkflow` repository, where exactly that "fix" shipped and left its
  automation inert while every run stayed green.
- GitHub keeps one pending run per concurrency group and cancels the previously pending one
  when a newer run queues. With the group keyed by branch, a stale event arriving after a
  useful merge trigger could cancel it, leaving a green bump unmerged with nothing
  reporting a failure. Keying by the verified commit removes that interaction; the commit
  job's non-force ref update is what actually serializes writes.

### Evidence

- `gh pr list --repo sympoies/nils-alfredworkflow --head sympoies:docs/enable-devlog-backfill
  --state all` returns nothing, while the same query with the bare branch name returns a
  pull request — the reason the owner-qualified form is not used here.
- The `isCrossRepository` field is returned by `gh pr list --json` and filters correctly in
  the same query shape used by both jobs.
- `bash scripts/ci/nils-cli-checks-entrypoint.sh --local-fast` passes on the change.

### Links

- <https://github.com/sympoies/nils-alfredworkflow/pull/238>

## 2026-09-13 - Bounded coordination receipts by aggregate bytes

### Result

- Added a 4 MiB per-principal budget over the serialized size of retained
  idempotency receipts, rejecting at the limit rather than evicting.
- Added Codex account failover: an account-aware auto-resume recovery policy,
  a switch to the next capacity-confirmed account before a resume, and an
  effective default account resolved and projected at launch.

### Why / context

- Count quotas bounded how many receipts a principal could retain but not how
  large they could be, so a principal could hold a small number of very large
  receipts and exhaust the store anyway. A byte budget closes the dimension the
  count quota left open.
- Rejecting at the limit rather than evicting is the important half. Evicting a
  retained idempotency key makes a later replay of that key look like a fresh
  request, which turns an overflow into a duplicate-execution bug - a strictly
  worse failure than a refusal.

### Evidence

- `cb6f6657` (#1706) the byte budget with its reject-not-evict reasoning,
  `6fd0de9c` (#1702) the account failover.

- `crates/agent-session/docs/README.md`

## 2026-09-13 - Lowered the CI retry budget on measured evidence

### Result

- Lowered nextest `retries` from 2 to 1 in the `ci` profile, replacing an
  earlier mitigation note with the measured basis for the new budget, and
  recorded the clusters still flaking.

### Why / context

- The decision was made from data, not intuition: retry depth was measured
  across 74 job-level JUnit files from two `main` windows, and all 29 flaky
  events passed on the first retry. The second attempt therefore never changed
  an outcome while costing wall-clock on every genuine failure.
- This pairs with `946a3157` (#1649), which enabled `flaky_summary` on both
  JUnit publish steps so a retried pass appears in the check people actually
  read. Without that visibility, reducing the budget would have been a guess;
  with it, masked flakes are countable.

### Evidence

- `70ad9b47` (#1704) carries the measurement in its commit body.

## 2026-09-09 - Typed the workspace lease protocol generation

### Result

- Typed the workspace lease protocol generation and bound a v2 `begin` to the
  call its target came from.

### Why / context

- An untyped generation is an integer that any caller can supply, which makes
  fencing only as strong as caller discipline. Typing it, and binding a `begin`
  to the originating call, means a lease operation cannot be reissued against a
  target it was not resolved for.
- This is the same defect class as the August default-branch flag removal: a
  guard that depends on the caller describing itself accurately is not a guard.

### Evidence

- `68f66fd2` (#1651) the typing, `0791a59a` (#1652) the call binding.

## 2026-09-03 - Added the target-scoped workspace lease protocol v2

### Result

- Added `workspace-lease resolve`, which classifies one exact tool execution
  into zero or more canonical repository targets and owns no durable state.
  Structured `write`, `edit`, and `str_replace_editor` mutations resolve
  exactly; read-only forms, unknown tools, and arbitrary shell programs are
  handled distinctly.
- Tiered the DSH policy groups and added an advise rule mode.

### Why / context

- v1 leased the workspace; v2 leases the targets a specific execution will
  actually touch. That is what allows two agents to work the same checkout on
  disjoint files without contending, which the coarse lease made impossible.
- `resolve` owning no durable state is the design constraint that keeps it
  safe to call speculatively: classification is a pure function of the
  execution, so it can run on every tool call without accumulating anything.
- An arbitrary shell program cannot be resolved exactly, so it is classified as
  such rather than guessed at - the honest answer being the one that lets the
  caller decide.
- The advise rule mode exists so a policy can be observed before it is
  enforced, which is how a tier gets promoted on evidence rather than on
  expectation.

### Evidence

- `556067bd` (#1600) the protocol, `6674fd7c` (#1616) the policy tiers and
  advise mode.

### Links

- `8f6c59bd` (#1488) the August v1 lease authority

## 2026-09-02 - Streamed attachment uploads to disk

### Result

- Attachment uploads now enforce configurable declared and observed byte
  ceilings without buffering request bodies, publishing private temporary files
  only after a successful sync and cleaning them up on failure or
  cancellation, with coverage for streaming timing, admission ordering, exact
  limits, cleanup, and compatibility.
- Admitted `block-agent-artifact-routing` to the `agent-hook` v1 allowlist and
  added starring of history sessions.

### Why / context

- Both a declared and an observed ceiling are needed: the declared size is
  attacker-supplied and the observed size only becomes known while reading, so
  trusting either alone leaves a hole. Enforcing both without buffering means a
  hostile body is refused mid-stream rather than after it has been held in
  memory.
- Publishing only after a successful sync is what makes a partially-written
  attachment unobservable; cleanup on cancellation is what keeps a refused
  upload from leaving residue in the private temporary area.

### Evidence

- `7485243f` (#1594) the streaming upload, `bf80fae0` (#1599) the allowlist
  admission, `8f5d6eba` (#1602) history starring.

## 2026-09-01 - Added the typed agent-hook data-policy evaluator

### Result

- Added a deterministic data-policy boundary evaluating sensitive output,
  machine-local paths, and protected roots through a strict content-free JSON
  contract, with every decision bound to the exact execution identity and
  coverage for structured, streamed, binary, and replay cases.
- Added the provider session history API with latest-context paging.

### Why / context

- The contract is content-free by design: a policy evaluator that receives the
  content it is judging becomes a second copy of the sensitive data, and its
  logs, errors, and replay records become new leak surfaces. Evaluating over
  descriptors rather than payloads keeps the boundary from being the breach.
- Binding decisions to the exact execution identity is what makes a replayed
  decision detectable rather than silently reusable.

### Evidence

- `4b855b3d` (#1583) the evaluator, `bf459255` (#1584) and `a92d0221` (#1586)
  the history API and paging.
