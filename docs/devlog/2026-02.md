# Development log - 2026-02

## 2026-02-27 - Landed metadata gates for split-prs and plan-issue

### Result

- Made plan lane assignment metadata-first: `split-prs` and `plan-issue`
  reject plans whose task metadata cannot support a deterministic grouping,
  instead of guessing from prose.
- Added the shared Markdown helper suite in `nils-common` so every generator
  that writes issue bodies and comments goes through one escaping and payload
  path.

### Why / context

- Auto-grouping originally inferred lanes from headings and dependency prose.
  That produced grouping decisions nobody could reproduce or review. Requiring
  declared metadata moved the failure from a silently wrong lane split to a
  validation error at the plan.
- Markdown emitted into GitHub bodies is an injection and truncation surface.
  Centralizing it was a prerequisite for the payload guard added earlier in the
  month (`df840676`).

### Evidence

- `d64562df` enforces the metadata gates; `7090a1e0` made auto grouping
  metadata-first.
- `ffd554b8` added the shared Markdown helper suite.

### Links

- `df840676` shared Markdown payload guard for GitHub body/comment writes

## 2026-02-22 - Converged Codex, Claude, and Gemini onto one provider runtime

### Result

- Extracted `codex-core` from `codex-cli`, added `claude-core` and `claude-cli`
  with a unified provider architecture, brought `gemini-cli` to Codex parity,
  and then merged `codex-core` and `gemini-core` into a shared provider runtime
  built on provider profiles plus runtime adapters.
- The per-provider core crates were removed from the workspace and publish
  metadata; the shared auth, path, config, JWT, JSON, error, and exec helpers
  moved into `nils-common`.

### Why / context

- The three provider CLIs are the same program with different auth files,
  rate-limit shapes, and session layouts. Three `*-core` crates made that
  similarity invisible and let the three lanes drift, which is what the parity
  work kept discovering.
- Collapsing to profiles plus adapters was done only after `gemini-cli` reached
  parity, so the merge had two real implementations to generalize from rather
  than one implementation and a guess.
- Parity and runtime contracts with oracle tests landed with the merge, so both
  CLI lanes are checked against a stated contract instead of against each
  other.

### Evidence

  `25f47afa` brought Gemini to parity, and `80f6937e` merged the cores.
- `1f634353` made provider auth file parsing happen once, and `3f2d959f`
  shared the auth secret-dir env resolver, closing two of the divergences the

  adapters in a single day, added flag help text and a zsh description audit,

## 2026-02-07 - Added agent-docs as the required-reading resolver

### Result

- Added the `agent-docs` CLI with a document resolver and baseline tooling, a
  resolve checklist format, and a linked-worktree fallback mode for required
  docs.

### Why / context

- Agents working in this workspace need to read the right subset of docs for
  the change at hand; reading everything is expensive and reading nothing
  produces policy violations. `agent-docs` made that subset a resolvable,
  declared thing rather than a prompt convention.
- The linked-worktree fallback (`e74d9704`) exists because agents commonly work
  in a detached worktree where the declaring repository root is not the current
  directory; without it, required-doc resolution silently found nothing.

### Evidence

- `b9240e0c` the CLI and resolver, `1257a553` the checklist format,
  `e74d9704` the worktree fallback.
