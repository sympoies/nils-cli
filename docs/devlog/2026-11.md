## 2026-11-13 - Forge identity audit file rotation and unasserted guard pins
<!-- devlog-id: 2026-11-13-forge-identity-audit-rotation -->

### Result

- The identity audit file `identity-audit.jsonl` now rotates by size: the
  active file never exceeds 4 MiB and four rotated copies (`.1` newest to `.4`)
  are kept, so at most five files and 20 MiB exist. Record format and mode 0600
  are unchanged.
- Rotation and append run under an advisory lock (`identity-audit.lock`), so
  concurrent writers lose and interleave no record and the record being written
  always lands whole in the new active file.

  parallel first runs of one caller can each record and the generic `deny`
  refusal record is uncapped, both now bounded by the rotation limit.

### Why / context

- The audit file had no size cap and a host already held tens of MiB (#3612,
  follow-up to #3596).
- Fleet step: a pre-existing oversized audit file is rotated whole on its first
  append and drops out after four further rotations; delete it by hand to
  reclaim space sooner.

### Evidence

- Unit tests fill the file past the limit and assert rotation, the bound, mode
  and a multi-writer run; three guard tests pin the stamp path, the automation
  marker with TTYs, and an EPIPE stderr; each guard test fails when its guard

## 2026-11-12 - secrets set stores values bare
<!-- devlog-id: 2026-11-12-issue-3544-secrets-set-bare-values -->

### Result

- secrets set now stores the stdin value bare as KEY=value (LF as the SOPS
  dotenv newline form); a value with a literal backslash followed by n is
  refused. secrets add already stored file bytes verbatim, so both share one
  contract.

### Why / context

- Quoted storage leaked the wrapping quotes to plain sops dotenv readers. SOPS
  dotenv keeps quotes, hash, dollar, backslash and edge whitespace as written,

## 2026-11-12 - Forge identity warns on unasserted non-interactive runs
<!-- devlog-id: 2026-11-12-unasserted-noninteractive-identity -->

### Result

- New identity policy key `unasserted_noninteractive = allow | warn | deny`
  (default `warn`) applies when `activation = "asserted-only"` and no principal
  is asserted in a non-interactive run (no TTY on stdin/stdout, or
  `INVOCATION_ID`, `GITHUB_ACTIONS` or `AGENT_SESSION_ID` set).
- `warn` prints one stderr line naming the fix and appends an audit record with
  caller argv0 and parent process base names only; `deny` refuses with
  `identity_unasserted_noninteractive` (exit 65).
- The stderr warning is `warning: forge identity: no principal asserted in a
  non-interactive run; set FORGE_IDENTITY_PRINCIPAL to a configured principal,
  or set the identity policy key unasserted_noninteractive = "allow" to keep the
  shared default account on purpose`; the key is `unasserted_noninteractive`.
- The warning prints once per process. Audit records are capped at one per
  caller (argv0 and parent) per hour, tracked by a stamp file under
  `forge-cli/unasserted-callers` in the state root, so scheduled automation
  writes at most 24 lines a day per caller. The decision is local (environment
  and policy file): no identity probe and no provider call is added. The cap
  holds for sequential runs; parallel first runs can each record, and under
  `deny` the generic refusal record is uncapped.
- Runs that assert a principal, `identity explain`/`doctor`, and raw `gh`
  callers are unaffected.

### Why / context

- Automation that forgot a principal silently used the host's default `gh`
  account and could exhaust its shared REST quota with no signal (#3596).
- Fleet step: hosts with an `asserted-only` policy now warn for automation that
  sets no `FORGE_IDENTITY_PRINCIPAL`; set the key to `deny` once owners declare
  principals.

### Evidence

- `nils-common` and `forge-cli` integration tests cover the three modes,
  detection rules, asserted pass-through and the secret-free audit record.
